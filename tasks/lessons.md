# Lessons

- 画面のスクリーンショットを伴う「アイコン」の要望では、アプリアイコンと画面内アイコンのどちらを指すかを画像内の対象から先に特定する。対象が画面内の反復要素なら、外観だけでなく操作領域・状態表示・既存データのフォールバックまで含めて設計する。
- Voicyなど参照UIの丸い画像は単なる装飾ではなく「発信者の識別子」である可能性を確認する。動画サムネイルへ置き換える前に、ユーザーが識別したい単位がコンテンツか発信者かを切り分ける。
- 比較表の後に優先推奨を別掲した場合、「全部採用」は推奨リストを指す可能性を優先する。実装範囲を広げる前に、直前の結論部分をスコープとして扱う。
- ユーザーが比較結果に対して「全部」と指定した場合、除外項目が明示されるまでは表全体を指す可能性も残る。特に「推奨の部分」という表現は推奨列全体を意味し得るため、項目を勝手に3件へ限定しない。
- `docs/`配下の要件定義書・設計書・実装計画書は、CLAUDE.mdのPR運用ルール（SKILL.md/CLAUDE.md本体はPR必須）の対象ではなく、作業ログ等と同じ「直接コミットで良い進行記録」として扱ってよい。運用が明文化されていない新種のファイルをPR経由にすべきか判断に迷った場合、SKILL.md/CLAUDE.mdとの類似性だけで厳しい方（PR必須）に倒さず、まずユーザーに一言確認する。
- iOS Simulator制御ツール（`mcp__Claude_Code_iOS_Simulator__control`）の`tap`座標は、screenshotの見た目上のピクセル位置ではなく`attach`/`launch`結果が返す「device points」（例: 402x874）の座標系で指定する。スクリーンショット画像を目視して座標を推測すると点空間の範囲（例:402）を超える値を使ってしまい、タップが無反応または意図しない要素に当たる。既知の基準点（タブバーの位置など）から点空間の割合で座標を逆算するとよい。`inspect`が使えるならそちらで正確な frame を取得する方が確実。
