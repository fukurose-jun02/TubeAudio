# サーバー起動とMac接続先設定の自動化 - 要件定義書

関連Issue: https://github.com/fukurose-jun02/TubeAudio/issues/12

###### 背景・課題

- Macのローカルサーバー（Flask、`server/app.py`）は、毎回ターミナルで`python3 app.py`を手動実行しないと起動しない
- MacのIPアドレスはDHCPで変わることがあり、変わるたびにiPhone側の「設定」タブでIPアドレスを打ち直す必要がある（本プロジェクトの作業履歴でも `192.168.1.6` → `192.168.1.11` → `192.168.3.126` と変化している）
- この2点が「サーバー起動の苦労」としてユーザーの継続的な負担になっている

###### ゴール

- Macを起動・ログインすれば、ユーザーが何もしなくてもTubeAudioサーバーが動いている状態にする
- IPアドレスが変わっても、iPhone側の設定を毎回変更しなくて済むようにする

###### 非ゴール（今回のスコープ外）

- サーバーの常時起動をMac以外（クラウド等）に移行すること
- Mac・iPhoneが異なるネットワークにいる場合の外部公開・リモートアクセス対応
- サーバーの認証・パスワード保護の追加

###### 機能要件

| ID | 内容 |
|---|---|
| F1 | Macにログインすると、TubeAudioサーバーが自動的に起動する |
| F2 | サーバープロセスが何らかの理由で終了した場合、自動的に再起動する |
| F3 | サーバーの標準出力・エラーはログファイルに残し、後から確認できるようにする |
| F4 | iOSアプリのデフォルト接続先を、IPアドレスではなくMacのBonjourホスト名（`<ホスト名>.local`）にする |
| F5 | 手動でサーバーを止めたい・状態を確認したい場合の手順をドキュメント化する |

###### 非機能要件

- **可逆性**: 自動起動の設定はいつでも簡単に無効化・削除できること（`launchctl unload` + plist削除）
- **影響範囲**: 既存の変換・検索・ライブラリ機能の動作を変更しない
- **前提**: Mac・iPhoneは同一WiFi（同一LAN、mDNSが機能するネットワーク）に接続していること

###### 受け入れ基準

- [ ] Macを再ログインしても、ユーザーが何も操作せずにサーバーが起動している
- [ ] `http://<Macのホスト名>.local:5001/` にiPhoneのブラウザ・アプリからアクセスできる
- [ ] iOSアプリの初期設定（未設定時のデフォルト値）が上記ホスト名になっている
- [ ] サーバーを強制終了しても自動的に再起動する
- [ ] 起動ログが `server/logs/`（または同等の場所）に残る

###### ヒアリング済みの決定事項

| 論点 | 決定 |
|---|---|
| 苦労の内容 | 「起動の手間」「IP再設定の手間」の両方 |
| 既存docs/の扱い | 完了済みのYouTube検索機能の内容を上書きし、docs/は常に「今取り組んでいる件」だけを保持する運用にする |
