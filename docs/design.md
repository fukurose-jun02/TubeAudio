# ライブラリのラジオ/BGM分類 - 設計書

前提: [requirements.md](requirements.md) の要件に基づく。

###### 全体方針

- カテゴリは、各音声のメタデータ(`AudioMetadata`)に1項目として持たせる。ファイルの場所や名前は変えない
- 保存先は従来どおり`LibraryMetadataStore`(ファイル名をキーにしたUserDefaults)。新しい保存場所は作らない

###### 分類の持たせ方の判断

| 案 | 採否 | 理由 |
|---|---|---|
| a. メタデータにカテゴリ項目を足す | **採用** | 変更が小さく、削除時の後始末も既存の処理に乗る。再生位置など他の状態も壊れない |
| b. カテゴリごとにフォルダを分ける | 見送り | 移し替えのたびにファイルを動かすことになり、再生位置・メタデータのキー(ファイル名)の管理が複雑になる |

###### 変更するもの

| ファイル | 変更内容 |
|---|---|
| `ios/TubeAudio/LibraryMetadataStore.swift` | `AudioCategory`(radio / bgm)を追加。`AudioMetadata`に`category: AudioCategory?`を追加(省略可能なので古いデータもそのまま読める)。`category(for:)`(未設定ならradio)と`setCategory(_:for:)`を追加 |
| `ios/TubeAudio/ContentView.swift` | `ConvertView`にカテゴリの選択を追加し、保存時に`AudioMetadata`へ入れる。`LibraryView`に上部の切り替えと、カテゴリでの絞り込み、移し替え操作を追加 |
| `ios/TubeAudio.xcodeproj/project.pbxproj` | バージョン1.11 |
| `ios/README.md` | 機能・画面構成の更新 |

###### 動作の詳細

- **未設定の扱い**: `metadata(for:)`がnil、または`category`がnilの音声は、radioとして扱う
- **移し替え**: メタデータが存在しない音声でも移せるよう、`setCategory`はメタデータがなければ空の値(チャンネル名なし・再生時間0)を作ってカテゴリだけ入れる
- **画面**: ライブラリ上部に2択のセグメント(ラジオ/BGM)を置く。その下に既存の「すべて/未再生」と並び順を置く。選択中のカテゴリで`displayedFiles`を絞る
- **空の表示**: 全体が空のときは従来の表示。選んだカテゴリだけが空のときは「ラジオ(BGM)はまだありません」を表示する
- **変換画面**: フォーマット・品質の並びにカテゴリの切り替えを追加する。変換完了後の「別の動画を変換」では、初期値(ラジオ)に戻す

###### 動作しなくなるケースと対処

- 古いバージョンのアプリに戻した場合、カテゴリ項目は無視されるだけで音声は消えない
- 同名のファイルは従来から衝突するため、カテゴリでも衝突しうる(今回の対象外)
